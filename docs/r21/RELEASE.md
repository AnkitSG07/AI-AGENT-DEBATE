# R21 — transfer picker and in-call controls

The transfer picker now opens before the network request. An exact call/attempt/owner/enrollment-bound directory performs one prefetch when the call becomes transferable, coalesces in-flight requests and reuses results for 15 seconds. A dedicated executor and control GET timeouts prevent unrelated background work from holding the picker. End, ownership/enrollment changes and screen destruction invalidate results. Actual invitations still perform fresh server authorization and reservation checks; cached availability never authorizes a transfer.

Server device discovery performs one fresh policy evaluation and one directory fetch, in parallel, instead of repeated policy reads. Authentication overlaps the independent call lookup. Bounded reservation reads remain parallel. Privacy-safe directory/reservation and handset transfer-device timing labels distinguish the remaining network and server time.

Mute gates real microphone capture immediately and acknowledges the SDK publication change asynchronously. Failed unmute remains muted, audio focus restoration preserves mute, and late responses cannot reopen a closed microphone. Control errors report the problem without ending a healthy call. Speaker uses the real SDK route and displays the confirmed route, including Bluetooth/wired fallback; it has no optimistic success state.

The existing microphone foreground service retains audio when the call screen is paused/destroyed, Back opens the source chat, another app opens or the UI task is removed. New executed tests cover those lifecycles and the exact ongoing-notification Return and End intents. No production lifecycle rewrite was needed.

Frozen validation: **846 backend/private HTTP/frontend VM checks**, **301 Android tests in 36 suites**, zero failures/skips, and zero lint errors (89 existing/current warnings). Debug instrumentation sources compile; instrumentation on a device and physical audio routing/latency were not run. APK signature matches R20, versionCode 21, package unchanged, bundled Firebase project and supplied logo verified. Existing R20 installation can be upgraded; no new Odoo embed is required.

Recent live measurements still put 2.3–2.6 seconds inside the LiveKit Answer/Dial request alone. R21 removes avoidable picker/control delays; it does not establish zero-latency audio or a verified two-second end-to-end guarantee. Transfer completion still depends on the destination operator accepting and its audio connection becoming ready.

Recording, typed handover notes and recording-based bilingual summaries are a newly requested feature and are **not included or enabled in R21**. SH Chat AI remains disabled. The proposed design is a manual Record control with a caller notice, an independent recording/transcription job, and a rolling Hindi/English handover brief stored against the Odoo call. Transfer attaches the latest completed brief and typed notes without waiting for AI; the receiver sees it before joining. Audio belongs in private object storage, not Firestore documents. Recording/storage/transcription allowances must be checked before selecting services or enabling usage-based processing.
