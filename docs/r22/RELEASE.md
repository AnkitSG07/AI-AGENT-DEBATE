# R22 — notes, recording and private call handover

The native call screen now uses compact, labelled icons. Incoming calls show Answer/Decline; initial connection shows Cancel; connected calls show Speaker, Mute, Notes, Record, Transfer and End. Private handover shows Complete, Cancel transfer and, once the other operator's audio is ready, Merge. Video and keypad are absent. The existing foreground call service and notification keep the call available while the operator returns to a chat or another app.

Transfer offers **Instant transfer** and **Transfer with message**. The latter keeps the customer in the same LiveKit room on quiet piano hold music while the two operators speak privately. Complete hands the customer to the destination only after fresh customer-audio evidence; Cancel restores the source operator. Merge joins the three participants. Both operator phones must run R22 for private handover. Existing instant transfer remains compatible with older supported builds.

The downloaded recording is **Gymnopédie No. 1**, uploaded by Teknopazzo under CC0. A quiet 45-second excerpt with gentle fades loops during private handover. Attribution and source links are in `media/assets/HOLD-MUSIC-LICENSE.md`. No generated audio or AI is used.

Notes support Hindi and English text and are saved explicitly to private Odoo attachments. The receiving operator can open Notes before answering a transferred call. Record starts only after the operator confirms the customer has been informed; Stop saves the final segment. Audio is archived as 30-second WAV segments in Odoo, and participating operators can review notes and recordings in Settings. A private operator-to-operator briefing is excluded from the customer recording. There is no transcription or AI summary.

The optional recording/hold process starts only for those features, with at most two simultaneous workers. Normal call setup does not start or await it. Audio processing, archival and retries stay outside the call-control event loop. A failed hold worker cancels the exact active private handover and restores the original call; it does not end the customer call. Notes and audio use no new Firestore polling or blob storage. Existing device authentication and message notification paths are unchanged; AI remains disabled.

Validation: **992 backend, HTTP and browser checks** and **304 Android tests** passed. Android release build, instrumentation-source compilation and lint completed with zero lint errors (102 warnings). An isolated real LiveKit SFU and three Chromium audio peers verified actual hold piano, private audio exclusion, conference audio, stopping music on merge, and recording continuity across a 30-second archive boundary. The worker used approximately 100 MiB RSS in that test. The 44 ms hold preparation measurement used an already-connected recording worker; it is not a cold-start or handset-latency measurement.

The isolated media run used generated test tones, without production WhatsApp, Firebase or Odoo credentials. GitHub Actions could not start because the account was locked for a billing issue; the complete backend/browser suite and media test instead passed in a separate free Render build. Physical phone audio, WhatsApp connector mixing and cold-start latency still require handset verification. Prior measured LiveKit Answer/Dial requests alone took about 2.3–2.6 seconds, so this release does not establish a guaranteed two-second end-to-end call connection.

Recording preserves already archived segments across an application restart, but an abrupt process crash or redeploy can lose the current unsaved segment (up to 30 seconds). Storage failures are displayed and leave the call connected. The free Render instance and shared CPU remain constraints; no paid service or billing change was introduced.

Install the signed `SH-Chat-1.0-r22.apk` over the existing app on both operator phones. Package and signing certificate are unchanged, and the supplied company logo is included. Deploy the matching backend commit; no Odoo embed replacement or schema migration is required. APK and test evidence hashes are recorded alongside this document.
